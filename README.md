# ashare-multifactor-lab

A 股中证500 多因子选股研究框架（个人项目）。

目标：用公开数据跑通「PIT 清洗 → 因子构建 → 中性化 → IC/分层检验 → 组合构建 → 扣费回测 → 稳健性归因」的完整流水线，产出可复现的代码和一份研究报告。

**当前正式研究区间为2016-01-01—2024-12-31，2015年仅用于历史预热。** 已完成数据层和五因子第一阶段；预处理、因子评价、组合与回测尚未实现。当前进度、验证结果、局限和下一步统一维护在本README，HANDOFF.md仅为停止维护的历史归档。

## 研究区间与数据预热

`config/base.yaml`统一区分两类起点：

```yaml
start: "2016-01-01"       # 正式研究/信号起点
end: "2024-12-31"
data_start: "2015-01-01"  # 数据覆盖起点，供动量和其他窗口预热
```

- 正式研究按月末取样，实际信号为2016-01-29—2024-12-31，共108个月、每期500只，54,000条记录，历史成员并集1,197只。
- raw和interim保留2015—2024完整数据。已有月末数据层仍有120期、60,000条记录和1,259只历史成员；这些数字包含2015预热期，不等于正式研究样本。
- `build_factors.py`默认读取研究start/end，只筛信号月份，行情预热不被截断。`adjust.py`、`universe.py`、`pit.py`默认读取data_start/end，防止未来重建时误删2015历史；本轮没有重建这三类输入。
- 抓取CLI默认数据覆盖仍为2015—2024，不读取base.yaml；下面的2015起抓命令是数据准备示例，不代表把2015纳入研究，也无需因本次改区间重新抓取。
- CLI显式`--start/--end`优先于配置；指定子区间会覆盖相应单一产物，须核对运行清单的范围。五因子仍可能因个股上市时间、历史无报价或财务缺失留空，研究从2016开始不保证每只股票都有完整历史。

### 6. 常见报错

- **`没有访问该接口的权限` / `积分不足`**：先用 `probe` 确认；`all` 会跳过没权限的表。
- **`频率超限(1次/小时)`**：小时级限制，脚本直接抛错；日历会自动改用 AkShare 生成并缓存。
- **`每分钟最多访问`**：脚本自动等 60 秒重试；嫌慢把 `--sleep` 调大。
- **空 DataFrame**：先确认那天是不是交易日，非交易日返回空是正常的。
- **`必填参数, ts_code`**：2000 分档的 `income` / `balancesheet` / `cashflow` 只能按单只股票查询；脚本已改成逐只抓。按报告期拉全市场需要 `*_vip` 接口（5000 分）。

## 数据加工：复权 → 股票池 → PIT

抓完 raw 数据后，按顺序跑三个脚本（都在项目根目录）：

以下2015起点为**含预热的数据覆盖区间**。当前raw/interim已完整保留该范围，本次调整研究起点无需重跑数据加工；无参数运行时也会使用base.yaml的data_start，正式研究月份由因子层另行筛选。

```powershell
# 1. 复权 + 收益 + 市值/换手
python src/mfl/data/adjust.py --start 20150101 --end 20241231

# 2. 中证500 月度股票池：ST / 上市天数 / 停牌 / 涨跌停
python src/mfl/data/universe.py --start 20150101 --end 20241231

# 3. 财务 PIT：事件表 + as-of 面板
python src/mfl/data/pit.py --start 20150101 --end 20241231
```

输出：

| 文件 | 内容 |
|---|---|
| `data/interim/prices.parquet` | 后复权价、日收益、vwap、市值、换手、PE/PB |
| `data/interim/index.parquet` | 中证500 收盘与日收益 |
| `data/interim/universe.parquet` | 每个调仓日的成分股与可交易标记 |
| `data/interim/fundamental_events.parquet` | 按公告日排列的财务事件 |
| `data/interim/fundamental_panel.parquet` | 对齐到 (date, code) 的 PIT 面板 |

三个脚本都只读 raw、写 interim，可以单独重跑，不改原始数据。

### 复权脚本

- 收益用后复权价 `close × adj_factor`；市值、换手、涨跌停用不复权价；
- 生成 `vwap = amount × 10 / volume`（Tushare 的 vol 是手、amount 是千元）；
- 缺失/非法复权因子的行情保留，复权价及缺口两侧收益留空，不跨缺口计算；可选每日指标缺失时仍保留原有列；
- 仅从本地历史读取区间前最后一条行情用于收益预热，没有历史时首条收益为空；真实停牌无行情的间隔保留复牌跨期收益；
- 打印缺失率、指标覆盖率、收益差异分位数和相关系数。相关系数不能替代异常记录检查。
- CLI 按年加工并流式写同一个 parquet，跨年收益使用本地前序行情预热；临时文件完整关闭后才替换最终产物。Pearson 使用中心化逐元素求和，避免本机 NumPy/BLAS 相关计算阻塞。
- `config/price_quality.yaml` 登记19条价格质量事件：18条普通边界按本地连续性推断校正累计因子基准，1条北汽蓝谷复杂股改保持未解决。每条记录原始因子锚点、日期、证据和状态；原始锚点改变时停止加工，不能静默沿用旧规则。这里的校正不代表数据商已确认真实公司行动。
- `price_quality.py` 只应用已登记规则：普通边界从当日起累计乘校正倍率，保留其他日期的真实分红/送转相对倍率；预热历史使用同样规则。`prices.adj_factor` 是加工后的有效因子，原始值仍在raw；列名、类型和主键不变。
- 北汽蓝谷2018-09-27的有效因子、复权价留空，当日及下一条实际行情收益为空。只隔离单日不能阻止端点法跳过缺口，后续任何跨期价格/收益窗口还须调用 `price_quality.price_window_validity`，拒绝触及未解决事件的窗口；该函数不保证其他数据缺口均已排除。事件后同一价格段仍可计算相邻收益，跨事件真实持仓权益尚待核验，不能填零或直接忽略。
- 价格修复专项验证：`python scripts/verify_price_quality_repair.py` 使用 `results/adj_factor_repair/prices_before.parquet` 历史基线逐行核对；`python scripts/audit_member_return_discrepancies.py` 列出19条raw差异并核验规则处理后的产物，未解决项单列。当前状态与局限见本README下文，历史前后对照见 `reports/adj_factor_repair_20261107.md`。

### 股票池脚本

- 每个自然月最后一个交易日取一次成分股快照（最近一期 `index_weight`）；
- 只使用当时有效且已公告的 `namechange`；缺失或冲突名称的 ST 状态保留未知，不回填当前名称，不允许新建仓；
- 上市满 120 个交易日的规则不变。用已安装 AkShare 包内离线 `data/calendar.json` 补充历史年龄日历，与 raw 重叠必须一致；不联网、不修改 raw。无可靠历史覆盖时只给年龄下界，不伪造精确天数；
- 直接读取 raw 行情，并结合 `suspend_d` 与最近实际交易判断全天停牌；无行情且缺乏停牌证据时保留未知，禁止成交；
- `tradable` 表示新建仓资格，`can_buy` 还须通过涨停约束；`can_sell` 不因 ST、上市年龄或名称未知而阻止卖出，但仍须有行情、非停牌并通过跌停约束。缺失/非法限价不假定可以成交；
- 月中截断不会制造假月末。上述状态属于信号日，回测必须在实际执行日重新检查，不能直接移用至下一交易日。

### PIT 脚本

- 非年报季度用 `TTM = 本期累计 + 上年年报 − 上年同期累计`，年报直接取全年累计；平均净资产采用本期末和上年同期末的简单平均，ROE_TTM 为小数比例；
- 报表知识时间为 `max(ann_date, f_ann_date)`，缺实际公告日时回退 `ann_date`，次一自然日生效；保留现有 raw 的各版本，所有历史依赖都按事件当时已公开的版本取值；
- 利润表、资产负债表、可选指标的公告触发当前报告期重算。历史报告修订不会使当前报告期倒退，可选指标不会推迟此前已可用的主财务数据；
- 同日冲突字段置空，保留阻断事件，直到后续明确版本恢复；非季末或非法日期记录告警并排除；
- 缺资产负债表时保留利润 TTM、ROE_TTM 留空；缺利润表仅输出 `fina_only`，不把年化 ROE 冒充 TTM。`roe_yearly` 等数据商原始指标保留原单位，不能与小数 ROE_TTM 混用；
- 事件快照包含 start 前的历史种子，但不含 end 后才生效的信息。只保证 raw 已保留版本的时间对齐，数据商未保留的原始财报数值不能从加工层恢复。

### 因子第一阶段：原值、质量和覆盖（2026-11-08）

在项目根目录、mfl环境运行：

```powershell
python scripts/build_factors.py
python scripts/check_factors.py
python -m pytest tests/test_factors.py -q
```

- 仅使用已有prices、universe、PIT月末面板、本地交易日历和显式价格质量规则，不抓数、不写raw或interim；不做去极值、标准化、中性化、因子评价、组合或回测。`config/base.yaml`中后续阶段的neutralize等参数在本阶段不启用。
- `config/factors.yaml`事先固定五因子定义和方向：EP用PIT归母净利润TTM除以同日总市值（万元转元）；ROE复用PIT的roe_ttm；MOM_12_1用P[m-1]/P[m-12]-1；REV_1M取当月收益的负数；TURN_20为最近20个市场交易日换手率转小数后均值取负。P是对应月份月末的有效复权价。财务报告期年龄大于550天留空，不以年化ROE或数据商PE替代。
- 月末收盘后生成信号，下一交易日执行；不机械重复shift。按同股完整历史计算后再取当期成员，不丢入池前历史。2015年保留作预热，不写入默认研究因子面板；首个研究信号2016-01-29的动量使用2015年月末价格。首版严格要求价格及换手窗口完整，缺报价不补零、不以最近20条报价冒充20个交易日。
- `data/processed/factors/raw.parquet`：保留全部月末(date,code)，五列是已按定义统一方向、尚未预处理的因子值；这里的raw不指data/raw原始数据目录。`quality.parquet`为每股每因子一行，保留base_value/value/direction、valid、eligible、首要及全部原因、价格窗口及观测数、财报日期/依赖时间、负利润和跨推断校正边界标记。
- valid表示该因子可计算；eligible只复制现有universe.tradable，不代表次日可成交。亏损EP和负ROE可以有效；不同因子缺失不导致整条股票池记录被删除。跨未解决公司行动的价格窗口调用price_window_validity拒绝；18条本地连续性推断不在因子层重复校正，只对跨边界窗口标记。
- `results/factors/`输出总体/月度/年度覆盖、缺失首要原因、数值分布和run_manifest.json；完整原因可能重叠，首要原因计数互斥。`reports/factor_coverage.md`为覆盖报告，不包含IC或收益评价。
- 构建前后校验全部raw/interim文件的内容、大小和修改时间，并记录输入、配置、价格规则、源码哈希、Git提交和工作区差异哈希及依赖版本。产物逐文件原子写入，完成清单最后发布；验收脚本核对清单和当前输入，并独立复算财务公式、月度完整窗口及20个交易日的换手均值。
- 默认信号范围读取base.yaml的start/end；可选`--start/--end`覆盖配置，仍保留完整本地行情预热。指定子区间会覆盖上述因子产物，清单记录请求区间、实际月末区间、data_start及base.yaml哈希。后续研究不能把子区间产物误作完整九年结果。
- 当前缺少历史行业分类、财报原始版本仍有限、价格连续性校正含推断，严格完整窗口也会排除有历史停牌的样本。覆盖率反映可计算性，不证明因子有效。

## 附录 A：raw 原始数据字典（金融入门版）

本附录按 **2026-11-07 本地文件的实际列名**整理：`data/raw/` 下有 14 个数据目录、59 个 Parquet 文件，下面分别列出全部 114 个字段条目（同名字段在不同表中分别解释）。这里只检查文件结构，没有重新下载或修改数据；目录和列名齐全不代表每个日期、每只股票都有数据。字段口径参考各节链接的 Tushare 官方文档，具体哪些字段进入加工结果，以当前项目代码为准。所有计算例子均为假设数字。

Parquet 可以理解为适合程序读取、体积较小的表格文件。`year=2024` 表示按年份分文件保存，`ts_code=000905.SH` 表示按指数代码分目录保存；这些目录名本身不属于新增业务字段。

### 阅读前：先认识单位、日期和基本概念

| 概念 | 面向初学者的解释 |
|---|---|
| 一行、一列 | 一列表示一种属性，例如收盘价；一行表示一条记录。日行情通常是一只股票一天一行，财报则可能是一只股票、一个报告期、一个公告版本一行。 |
| 股票与指数 | 股票代表对一家公司的权益；指数把一组股票按规则组合成一个衡量整体表现的数值。指数的“5000点”不是一股卖5000元，也不等于ETF的交易价格。 |
| 股票代码 | `ts_code` 通常为数字代码加市场后缀，例如 `000001.SZ`。股票中 `.SH`、`.SZ`、`.BJ` 分别标识上海、深圳、北京市场；指数应按数据源提供的完整代码识别，不能凭数字代码猜测。代码按字符串保存，避免丢掉开头的零。 |
| 日期 | 原始日期通常写为 `YYYYMMDD`，例如 `20240331`。`trade_date` 是交易或快照日期；`ann_date` 是公告日期；财务表的 `end_date` 是报告期截止日；更名表的 `end_date` 则是名称有效期结束日。 |
| 百分数与小数 | 标注 `%` 的字段，`5` 表示5%，换成参与小数运算的比例是 `0.05`。加工后的股票收益 `ret=0.05` 也表示5%，两种写法不能直接混加。 |
| 价格、成交额、股数 | 股票价格通常为元/股；`daily`、`index_daily` 的成交额为千元、成交量为手；本项目A股计算按1手=100股。`daily_basic` 的股本为万股、市值为万元；三张财务报表的金额为元。不同表连接后仍须先统一单位。 |
| 空值 | `NaN`、`None`、空字符串可能表示未披露、不适用、没有抓到或数据源未提供，不能统一当成0。缺少停牌记录也不等于已经确认正常交易。 |
| 收入、利润、现金 | 收入是卖货或提供服务形成的业务收入；利润是按会计规则扣除成本费用等后的结果；现金流反映实际资金流入流出。例如赊销可能已经确认收入和利润，但还没收到货款。 |
| 资产、负债、净资产 | 资产包括现金、存货、厂房等资源；负债包括借款、应付款等义务；净资产是资产减负债后归股东的账面权益。净资产与股票市场给公司的估值不同。 |
| 市值、估值倍数 | 总市值可理解为股价乘总股数。PE、PB、PS分别把市值与利润、净资产、营业收入比较，单位为“倍”；它们没有统一的“越小越好”结论。 |
| TTM | Trailing Twelve Months，即最近12个月。用来减少直接比较一季、半年和全年累计业绩时的期间差异。 |
| 年化 | 把当前期间的结果折算到一年尺度，用于比较；它不代表未来一年保证实现，也不等同于已经发生的最近12个月业绩。 |
| PIT与未来信息 | PIT要求历史决策只使用当时已经公开的数据。例如3月31日结束的季报在4月才公布，不能从3月31日起就使用里面的利润。项目由 `pit.py` 按公告知识时间对齐。 |

### 14类数据分别回答什么问题

| 小节 | raw目录 | 它回答的问题 | 当前项目中的用途 |
|---|---|---|---|

### A.1 交易日历：`trade_cal`

**位置：** `data/raw/trade_cal/data.parquet`。**一行表示：** 一个交易所的一个自然日，包含开市日和休市日。

**用途：** 建立时间轴，区分“过去120个自然日”和“过去120个交易日”，寻找每个月最后一个交易日。周末、节假日通常不能直接当成交易日。字段依据：[Tushare交易日历](https://tushare.pro/document/2?doc_id=26)。

| 字段（原始列名） | 中文名称 | 单位／取值 | 新手解释与使用方式 |
|---|---|---|---|
| `exchange` | 交易所标识 | 文本，如 `SSE`、`SZSE` | 表明采用哪个市场的开休市安排，分别对应上海、深圳交易所；项目抓取时使用上交所日历。 |
| `cal_date` | 自然日日期 | `YYYYMMDD` | 该行对应的日历日期，不保证当天可以交易。 |
| `is_open` | 是否开市 | `1`=开市，`0`=休市 | 用于提取交易日；原始文件中可能以字符串或数值形式保存。 |
| `pretrade_date` | 上一个交易日 | 日期，或空字符串 | 最近一个早于本日的交易日，不一定是昨天。项目用AkShare兜底生成日历时，这一列会留空。 |

**使用提醒：** `is_open=1` 只说明市场开市，某只股票仍可能停牌。上市年龄需要足够早的历史日历，不能把文件起点误当成股票上市起点。

### A.2 股票基础资料：`stock_basic`

**位置：** `data/raw/stock_basic/data.parquet`。**一行表示：** 一只股票在抓取时得到的基础资料快照。

**用途：** 识别股票、取得上市和退市日期。项目分别查询上市、退市、暂停上市三类股票，避免只看今天还上市的公司而遗漏历史失败样本；这种遗漏叫“幸存者偏差”。字段依据：[Tushare股票基础信息](https://tushare.pro/document/2?doc_id=25)。

| 字段（原始列名） | 中文名称 | 单位／取值 | 新手解释与使用方式 |
|---|---|---|---|
| `ts_code` | 完整股票代码 | 字符串 | 跨表连接用的股票身份标识，包含市场后缀。 |
| `symbol` | 数字证券代码 | 字符串，通常为6位 | 不带市场后缀，开头的零有意义；跨市场连接优先用完整的 `ts_code`。 |
| `name` | 股票简称 | 文本 | 抓取时得到的名称，不能据此断定很多年前是否属于ST股票。 |
| `area` | 所属地域 | 文本 | 数据商提供的公司地域分类，不代表公司只在该地域经营。 |
| `industry` | 所属行业 | 文本 | 数据商的行业归类，可帮助理解业务；当前快照不是带历史生效时间的行业分类表。 |
| `market` | 市场板块类别 | 如主板、创业板、科创板等 | 说明股票属于哪个板块；板块类别与上海、深圳等交易所名称不是同一个维度。 |
| `list_date` | 上市日期 | `YYYYMMDD` | 用来计算上市交易日年龄，筛除上市时间过短的股票。 |
| `delist_date` | 退市日期 | `YYYYMMDD`，可能为空 | 表示退出上市交易的日期；空值不能单独证明任意历史时点都能正常交易。 |
| `is_hs` | 沪深港通标识 | `N`=非标的，`H`=沪股通，`S`=深股通 | 沪深港通是内地与香港市场间的股票交易通道；该列表示相应标的身份，不是股票自身上市交易所的简单缩写。 |
| `list_status` | 上市状态 | 本项目查询 `L`=上市、`D`=退市、`P`=暂停上市 | 抓取脚本根据查询类别补入这一列。暂停上市和某一天临时停牌不同；此列也不是逐日历史状态。 |

**使用提醒：** 当前名称、行业和状态不能直接回填到过去。研究某年股票是否进入中证500，必须查看该年的 `index_weight`。

### A.3 历史更名记录：`namechange`

**位置：** `data/raw/namechange/data.parquet`。**一行表示：** 一只股票的一段名称使用记录。

**用途：** 根据历史名称中的ST标记辅助识别当时的风险警示状态。ST、*ST是特殊处理或退市风险警示相关标记；名称变化也可能只是普通改名，不能把每次更名都当作风险事件。字段依据：[Tushare股票曾用名](https://tushare.pro/document/2?doc_id=100)。

| 字段（原始列名） | 中文名称 | 单位／取值 | 新手解释与使用方式 |
|---|---|---|---|
| `ts_code` | 股票代码 | 字符串 | 标识是哪只股票的更名记录。 |
| `name` | 当期证券简称 | 文本 | 该段历史期间使用的名字；项目检查其中是否包含 `ST`，作为ST识别依据之一。 |
| `start_date` | 名称开始日期 | `YYYYMMDD` | 表示该名称何时开始使用，不是公司上市日期。 |
| `end_date` | 名称结束日期 | `YYYYMMDD`，可能为空 | 表示该名称有效期何时结束；此处不表示财务报告期，空值通常表示没有记录结束日期。 |
| `ann_date` | 更名公告日期 | `YYYYMMDD`，可能缺失 | 帮助判断这个名称在当时是否已经公开，不能只看开始日期而忽略公告时间。 |
| `change_reason` | 名称变更原因 | 文本 | 描述普通更名、增加或撤销ST等原因，可辅助人工理解事件。 |

**当前处理：** `universe.py` 以开始日期与可取得公告日期的较晚者作为知识起点，并检查结束日期。名称缺失或存在冲突时保留未知，不以今天的简称填补历史。

### A.4 股票日线行情：`daily`

**位置：** `data/raw/daily/year=YYYY/data.parquet`。**一行表示：** 一只股票一个有行情记录的交易日。

**用途：** 描述价格和成交情况，是计算收益率、动量、反转以及判断当天有无实际行情的基础。本表为未复权行情；停牌期间通常没有对应日线。字段及参考昨收口径依据：[Tushare A股日线行情](https://tushare.pro/document/2?doc_id=27)。

| 字段（原始列名） | 中文名称 | 单位／取值 | 新手解释与使用方式 |
|---|---|---|---|
| `ts_code` | 股票代码 | 字符串 | 与复权因子、每日指标等按代码和日期连接。 |
| `trade_date` | 交易日期 | `YYYYMMDD` | 该笔日行情所属日期。 |
| `open` | 开盘价 | 元/股 | 当天开盘形成的价格，反映当天交易开始时的价格水平。 |
| `high` | 最高价 | 元/股 | 当天成交价格的最高值，不等于每天允许的涨停价。 |
| `low` | 最低价 | 元/股 | 当天成交价格的最低值，不等于每天允许的跌停价。 |
| `close` | 收盘价 | 元/股 | 当天收盘形成的未复权价格；项目用它乘复权因子得到 `close_adj`。 |
| `pre_close` | 参考昨收价 | 元/股 | 数据商用于计算当日涨跌的昨收参考价；遇除权除息可调整，不应总当成上一行 `close` 的原样复制。 |
| `change` | 当日涨跌金额 | 元/股 | 按本表参考价计算，通常为 `close - pre_close`；正数上涨、负数下跌。 |
| `pct_chg` | 当日涨跌幅 | % | 通常为 `(close / pre_close - 1) × 100`。数值 `2` 表示上涨2%；项目用它辅助检查自行计算的复权收益。 |
| `vol` | 成交量 | 手 | 当天撮合成交的股票数量；项目按1手=100股换算。同一批股票可能反复成交，不代表有这么多不同投资者或不同股数换手。 |
| `amount` | 成交金额 | 千元 | 当天成交资金规模，数值1000表示100万元；和财报中的“元”需要区分。 |

**小例子：** 假设 `amount=2000` 千元、`vol=1000` 手，则全天成交均价约为 `2000×1000÷(1000×100)=20` 元/股，即 `adjust.py` 的 `vwap=amount×10/vol`。表内没有 `vwap`、`ret`、`close_adj`，它们属于加工后字段。

### A.5 复权因子：`adj_factor`

**位置：** `data/raw/adj_factor/year=YYYY/data.parquet`。**一行表示：** 一只股票某天的复权系数。

**用途：** 分红、送股、转增等会改变每股报价或股份数量，使直接比较原价容易出现机械断点。复权因子用于把价格换到可比较的历史尺度。字段依据：[Tushare复权因子](https://tushare.pro/document/2?doc_id=28)。

| 字段（原始列名） | 中文名称 | 单位／取值 | 新手解释与使用方式 |
|---|---|---|---|
| `ts_code` | 股票代码 | 字符串 | 必须匹配同一只股票的价格。 |
| `trade_date` | 因子对应交易日 | `YYYYMMDD` | 必须匹配同一天的价格，不能只按股票代码连接。 |
| `adj_factor` | 复权因子 | 无量纲系数 | 项目定义 `close_adj=close×adj_factor`，再用相邻后复权价计算收益。因子本身不是股价，也不是当天收益率。 |

**小例子：** 仅为理解送转情形，假设每股10元、因子1；随后股份数量翻倍、每股报价变成5元、因子变成2，两天后复权价格都为10，不会被误算为亏损50%。实际公司行动的因子以数据商为准。复权价格用于收益比较，涨跌停和实际报价比较仍用未复权价；不同股票的因子绝对大小不能用来给股票排名。项目对缺失或非正因子留空，不跨过因子缺口计算收益。

### A.6 每日估值与交易指标：`daily_basic`

**位置：** `data/raw/daily_basic/year=YYYY/data.parquet`。**一行表示：** 一只股票某个交易日的估值、股本和活跃度快照。

**用途：** 为规模、估值和换手等因子提供输入。它包含财务派生指标，但其日期是交易日；不能把其中的PE直接理解为已经经过本项目严格财报版本审计的结果。字段、单位和股息筛选口径依据：[Tushare每日指标](https://tushare.pro/document/2?doc_id=32)。

| 字段（原始列名） | 中文名称 | 单位／取值 | 新手解释与使用方式 |
|---|---|---|---|
| `ts_code` | 股票代码 | 字符串 | 与当天日线连接。 |
| `trade_date` | 指标交易日 | `YYYYMMDD` | 指标对应的市场日期，不是所引用财报的报告期。 |
| `close` | 当天收盘价 | 元/股 | 该日的未复权报价；加工代码以 `daily` 的价格为主，没有重复合入本列。 |
| `turnover_rate` | 流通股口径换手率 | % | 成交股数相对无限售流通股数的比例。数值3表示相当于该口径股本的3%成交，用于观察活跃程度。 |
| `turnover_rate_f` | 自由流通股口径换手率 | % | 使用自由流通股数作为分母，与上一列分母不同，不能混为同一指标。 |
| `volume_ratio` | 量比 | 倍 | 当前成交量相对历史平均成交量的比值，用于观察放量或缩量；如2表示相对其参考均量约为两倍。具体均量窗口依数据商口径，项目未自行重算。 |
| `pe` | 市盈率PE | 倍 | 市值相对于非TTM利润口径的估值倍数，可理解为市场为每1元相应利润支付多少元；官方对亏损公司的PE可能留空。 |
| `pe_ttm` | 滚动市盈率 | 倍 | 用最近12个月净利润作分母的市盈率；如20倍表示市值约为对应年度尺度利润的20倍，不表示承诺20年回本。 |
| `pb` | 市净率PB | 倍 | 市值相对账面净资产的倍数，数据商分母扣除其他权益工具；用于比较市场估值与账面权益。不能简单把整个集团总资产当分母。 |
| `ps` | 市销率PS | 倍 | 市值除以最新年报营业收入，衡量市场为每1元年收入支付多少元；收入不是利润。 |
| `ps_ttm` | 滚动市销率 | 倍 | 分母改成最近12个月营业收入，便于减少报告期间差异。 |
| `dv_ratio` | 股息率 | % | 数据商按除息日落在上一年度的现金派息计算的收益比例；它衡量历史分红相对价格的大小，不是未来保证收益。 |
| `dv_ttm` | 滚动股息率 | % | 采用近12个月除息且分红报告期满足官方12个月筛选口径的现金派息。与上一列时间窗口不同，不应无条件互换。 |
| `total_share` | 总股本 | 万股 | 公司发行股份总数，数值10000表示1亿股；不是市值。 |
| `float_share` | 流通股本 | 万股 | 按数据商口径可流通的股数，区别于全部已发行股份。 |
| `free_share` | 自由流通股本 | 万股 | 在流通股基础上按数据商规则进一步排除长期、战略性等不自由流通持股后的口径，不等同于 `float_share`。 |
| `total_mv` | 总市值 | 万元 | 股价乘总股本；数值100000表示10亿元。它是市场估值，不是公司账上的现金。 |
| `circ_mv` | 流通市值 | 万元 | 股价乘流通股本，反映流通部分的市场价值，与总市值的股数口径不同。 |

**当前加工范围：** `adjust.py` 保留两种换手率、`total_share`、`float_share`、两种市值、`pe_ttm` 和 `pb`。量比、PE、PS、股息率、自由流通股本等仍在raw中，尚未全部传到 `prices.parquet`。

**单位例子：** 假设股价10元、总股本10000万股，则总市值为100000万元，即10亿元。若自行用财报中的“元”重算估值，须先把这里的“万元”乘10000。数据源的空PE不能直接改成0后再求倒数；估值较低也可能伴随亏损风险、周期变化或其他问题。

|---|---|---|---|
| `index_code` | 所属指数代码 | 当前为 `000905.SH` | 表示这份成分名单属于哪个指数。 |
| `con_code` | 成分股票代码 | 字符串 | 指数包含的具体股票；加工后统一改名为 `code`。 |
| `trade_date` | 快照日期 | `YYYYMMDD` | 表示这份名单和权重对应的时点，选择快照时不能使用晚于信号日的记录。 |
| `weight` | 指数成分权重 | 百分比口径 | 表示该股票在指数中的占比，如0.5表示0.5%，换成小数权重为0.005；完整一期权重合计通常应接近100，差异还需检查缺失和舍入。 |

**当前处理：** `universe.py` 为每个完整月末选不晚于当日的最近一整期快照，并保存原始快照日期。指数权重不是本项目策略的目标仓位，也不是每只股票收益率；月度数据无法完整还原月内每一次成分调整。

### A.9 利润表：`income`

**位置：** `data/raw/income/data.parquet`。**一行表示：** 一只股票、一个报告期的一次可取得的报表版本。相同报告期可能有不同公告或修订记录，不能简单认定一只股票一个季度永远只有一行。

**用途：** 观察公司在一段时间内的收入、成本费用扣除后的利润。项目主要使用归母净利润计算最近12个月利润，供盈利质量和估值研究使用。字段和报表类型依据：[Tushare利润表](https://tushare.pro/document/2?doc_id=33)。

| 字段（原始列名） | 中文名称 | 单位／取值 | 新手解释与使用方式 |
|---|---|---|---|
| `ts_code` | 股票代码 | 字符串 | 标识发布这份财报的上市公司。 |
| `ann_date` | 公告日期 | `YYYYMMDD` | 数据源记录的公告时间，决定历史投资者可能何时知道财报内容，区别于经营期间截止日。 |
| `f_ann_date` | 实际公告日期 | `YYYYMMDD`，可能缺失 | 用来进一步确定信息何时真正公开；项目与 `ann_date` 取可取得日期中的较晚者，再推迟一个自然日使用。 |
| `end_date` | 报告期截止日 | 通常为 `0331`、`0630`、`0930`、`1231` 结尾 | 例如 `20240630` 表示截至2024年6月30日的报告期，不表示投资者6月30日就已知道财报。 |
| `report_type` | 报表口径类型 | 编码；项目请求并使用 `1` | `1`代表合并报表，即把公司及纳入合并范围的子公司作为整体核算；`2`为单季合并，`4`为调整合并，`5`为调整前合并，`6`为母公司口径等。其他完整编码见官方文档，不能无差别混算。 |
| `comp_type` | 公司类型 | `1`一般工商业、`2`银行、`3`保险、`4`证券、`7`多元金融 | 不同类型公司财报结构不同，例如银行收入结构不同于制造企业；它不是股票所属交易板块。 |
| `basic_eps` | 基本每股收益 | 元/股 | 用按会计准则确定的普通股股东利润及加权平均股数计算，每股对应多少利润；不代表每股实际分红，也不代表股价。 |
| `n_income_attr_p` | 归属于母公司股东的净利润 | 元 | 集团税后利润中归属于上市公司母公司股东的部分，扣除了属于子公司其他股东的少数股东损益；这是项目计算利润TTM的核心输入。 |
| `revenue` | 营业收入 | 元 | 公司销售产品、提供服务等确认的收入；收入很高仍可能亏损。金融企业的业务口径须结合其报表结构理解，不能默认等于所有企业的营业总收入。 |
| `operate_profit` | 营业利润 | 元 | 按报表口径，在收入扣除相关成本费用并考虑相应收益、损失项目后形成的营业利润；不是简单“销售额减进货成本”的毛利。 |
| `total_profit` | 利润总额 | 元 | 在营业利润基础上考虑营业外收支等后的税前利润；还没有扣除所得税，不能直接当作归母净利润。 |

**先理解累计数：** 当前 `report_type=1` 下，利润金额通常是年初至报告期末的累计值。Q1是1—3月，半年报是1—6月，三季报是1—9月，年报是1—12月。因此全年利润不能把四张累计报表直接相加。若半年累计利润30元、一季度累计10元，则第二季度单季利润为20元；每股收益涉及加权股数，不能照搬利润金额的减法求单季EPS。

**TTM例子：** 假设本年半年累计利润30、上年全年50、上年半年20，则最近12个月利润为 `30+50-20=60`。年报直接使用全年利润。所有依赖报表都必须在当时已经公开，不能在历史上使用日后才出现的修订数字。

**项目时间规则：** 对有实际公告日的记录，知识日取 `max(ann_date, f_ann_date)`，缺实际公告日则回退公告日，下一自然日生效。例如假设报告期是3月31日、4月25日公告，本项目最早从4月26日开始使用，并在实际信号日向后匹配。最终因子应读取PIT事件表或面板，不能自行按 `end_date` 直接连接原始财报。raw没有留存的历史原始版本也无法靠PIT加工恢复。

### A.10 资产负债表：`balancesheet`

**位置：** `data/raw/balancesheet/data.parquet`。**一行表示：** 一只股票某个报告期末的一次资产负债报表版本。

**用途：** 观察公司在一个时点拥有多少资源、承担多少义务，以及股东的账面权益。与利润表的“一段期间”不同，这张表主要是“期末存量快照”。字段依据：[Tushare资产负债表](https://tushare.pro/document/2?doc_id=36)。

| 字段（原始列名） | 中文名称 | 单位／取值 | 新手解释与使用方式 |
|---|---|---|---|
| `ts_code` | 股票代码 | 字符串 | 标识报表对应的上市公司。 |
| `ann_date` | 公告日期 | `YYYYMMDD` | 表示这份资产负债信息公开的日期，不能按报告期末提前使用。 |
| `f_ann_date` | 实际公告日期 | `YYYYMMDD`，可能缺失 | 与公告日共同确定保守知识日，处理规则与利润表一致。 |
| `end_date` | 资产负债表日 | 报告期截止日 | 例如6月30日表示当天期末的资产与负债情况，不是上半年资产数的累计和。 |
| `report_type` | 报表口径类型 | 项目使用 `1` 合并报表 | 区分集团合并、母公司、调整前后等口径；应与利润所采用的公司范围相匹配。 |
| `total_assets` | 总资产 | 元 | 企业控制的各类资源的账面总额，包括现金、应收款、存货、设备等；不等于现金余额或股票总市值。 |
| `total_liab` | 总负债 | 元 | 企业承担的借款、应付款等义务总额。负债不全是需要付利息的银行贷款，不能直接视为有息债务。 |
| `total_hldr_eqy_exc_min_int` | 归母股东权益 | 元 | 股东权益中属于母公司股东的部分，不包括子公司少数股东权益；项目使用它计算ROE_TTM的平均净资产分母。 |

**会计关系：** 合并口径通常满足“总资产=总负债+包含少数股东权益的全部股东权益”。本地只保留了归母权益，因此不能强行要求 `total_assets-total_liab` 恰好等于 `total_hldr_eqy_exc_min_int`，两者还可能相差少数股东权益。

**当前处理：** `pit.py` 取本期末与上年同期末归母权益的简单平均，再计算 `roe_ttm=归母净利润TTM/平均归母权益`，以小数保存；平均权益不大于0时留空。期末权益是时点数，不能把四个季度权益相加当全年权益。市值与净资产也不能只看数值大小比较，还要先统一“万元”和“元”。

### A.11 现金流量表：`cashflow`

**位置：** `data/raw/cashflow/data.parquet`。**一行表示：** 一只股票一个报告期的一次现金流报表版本。

**用途：** 观察经营活动是否真正带来现金，可与利润对照，帮助理解“账面赚钱但暂未收款”等现象。现金流还分经营、投资、筹资三类，本地目前只保留了其中的经营活动净额。字段依据：[Tushare现金流量表](https://tushare.pro/document/2?doc_id=44)。

| 字段（原始列名） | 中文名称 | 单位／取值 | 新手解释与使用方式 |
|---|---|---|---|
| `ts_code` | 股票代码 | 字符串 | 标识报表对应公司。 |
| `ann_date` | 公告日期 | `YYYYMMDD` | 决定何时可以知道报告中的现金流数据。 |
| `f_ann_date` | 实际公告日期 | `YYYYMMDD`，可能缺失 | 若未来纳入因子加工，应与公告日一起按项目PIT规则确定知识时间。 |
| `end_date` | 报告期截止日 | `YYYYMMDD` | 表示现金流统计期间的截止日，不是信息公开日期。 |
| `report_type` | 报表口径类型 | 项目请求 `1` 合并报表 | 当前经营现金流通常为年初至报告期末累计；不能和单季、母公司等口径混用。 |
| `n_cashflow_act` | 经营活动现金流量净额 | 元 | 经营活动现金流入减流出后的净额。正数表示本期经营活动净带来现金，负数表示净消耗现金；它不是公司期末现金余额，也不包含全部投资和融资现金流。 |

**小例子：** 假设一笔销售确认100元收入，80元成本费用形成20元利润，但客户尚未付款，同时公司已经支付80元款项，则利润为正而相关现金流可能为负。实际经营现金流还受存货、往来款和其他项目影响，单次负值不能直接认定公司一定经营恶化。

**当前加工范围：** `fetch.py` 已抓取本表，但当前 `pit.py` 没有读取它，财务面板没有经营现金流字段。后续若新增现金流因子，需要先增加按公告版本处理的PIT加工，不能绕过知识时间直接使用raw。

### A.12 数据商财务指标：`fina_indicator`

**位置：** `data/raw/fina_indicator/data.parquet`。**一行表示：** 一只股票、一个报告期的一次可取得财务指标记录。

**用途：** 提供数据商已经计算好的盈利、增长、资本回报与负债指标，减少自行从完整报表推导的工作。不同指标的分子、分母和期间可能不同，应按名称及数据商口径理解。字段依据：[Tushare财务指标](https://tushare.pro/document/2?doc_id=79)。

| 字段（原始列名） | 中文名称 | 单位／取值 | 新手解释与使用方式 |
|---|---|---|---|
| `ts_code` | 股票代码 | 字符串 | 标识财务指标对应公司。 |
| `ann_date` | 公告日期 | `YYYYMMDD` | 本表未保留实际公告日列，当前PIT加工按该公告日的下一自然日生效。 |
| `end_date` | 报告期截止日 | `YYYYMMDD` | 指标所属期间或期末日期；同一个日期下，各字段仍可能有不同的期间计算规则。 |
| `roe` | 净资产收益率ROE | % | 从股东投入资本对应账面权益的角度衡量盈利能力，概念上是利润相对净资产的回报；例如10表示10%。它不是股票价格收益率，具体分母以数据商口径为准。 |
| `roe_waa` | 加权平均净资产收益率 | % | 进一步考虑期内净资产变化的时间权重，例如期中新增资本并非从期初就已投入；不要与普通ROE不加区分地替换。 |
| `roe_dt` | 扣非净资产收益率 | % | 采用扣除非经常性损益后的盈利口径，减少部分偶发项目的影响；不能把它直接等同于未来稳定回报。 |
| `roe_yearly` | 年化净资产收益率 | % | 把当前期间资本回报折算到一年尺度的指标，既不是未来利润预测保证，也不是本项目自行计算的最近12个月 `roe_ttm`。 |
| `roa` | 总资产报酬率ROA | % | 从企业整体资产而非只从股东权益的角度衡量报酬；与ROE分母不同，也不能直接当作净利润除总资产的另一名称。具体报酬口径遵循数据商定义。 |
| `netprofit_yoy` | 归母净利润同比增长率 | % | 比较本报告期归母利润和上年同期利润。假设同期利润从100变120，则增长20%；上年亏损或基数接近0时，数值可能难以直接解释。 |
| `grossprofit_margin` | 销售毛利率 | % | 通常体现收入扣除营业成本后剩余毛利占收入的比例；尚未扣除全部期间费用、税费等，不等于净利率。 |
| `netprofit_margin` | 销售净利率 | % | 衡量每100元销售收入最终形成多少相应口径净利润；净利润与归母利润可能不同，精确计算以数据商口径为准。 |
| `debt_to_assets` | 资产负债率 | % | 通常为总负债除总资产乘100。假设资产100、负债60，则为60%；并非“负债占市值的比例”，不同行业的正常水平也不同。 |
| `eps` | 基本每股收益 | 元/股 | 每股对应的会计利润指标，与利润表的 `basic_eps` 概念相近；公告版本和计算期间不一致时不能盲目互相填补。 |
| `bps` | 每股净资产 | 元/股 | 账面股东权益摊到每股的数额，不是股价；需匹配相同权益、股数与时点口径。 |

**小例子：** 假设收入100、营业成本60，则毛利40、毛利率40%；再扣其他费用和税等后净利润10，则净利率10%。毛利率和净利率衡量不同层次的利润。

**当前加工范围：** PIT事件主要补入 `roe_yearly`、`grossprofit_margin`、`debt_to_assets`、`eps`、`bps`，其余原始指标没有全部输出。项目自行计算的 `roe_ttm=0.10` 与本表百分数写法的10都可以表示10%，但二者的期间和净资产算法仍可能不同，不能仅除以100就认定完全相同。可选指标晚公告，不会推迟已经可用的主财务数据。

### A.13 每日涨跌停价格：`stk_limit`

**位置：** `data/raw/stk_limit/year=YYYY/data.parquet`。**一行表示：** 某只证券某天的数据商涨跌停价记录。

**用途：** 让组合模拟考虑买不到、卖不出的可能性。涨跌停是允许价格边界，不是当天实际最高、最低成交价。不同板块、风险状态和特殊日期的规则会有差异，因此项目读取实际限价，不统一假设所有股票都是相同涨跌幅。字段依据：[Tushare每日涨跌停价格](https://tushare.pro/document/2?doc_id=183)。

| 字段（原始列名） | 中文名称 | 单位／取值 | 新手解释与使用方式 |
|---|---|---|---|
| `trade_date` | 限价对应交易日 | `YYYYMMDD` | 必须使用准备成交当天的限价，不能直接沿用前一天。 |
| `ts_code` | 证券代码 | 字符串 | 接口覆盖范围可能超过研究股票池，使用时与目标股票代码连接。 |
| `up_limit` | 涨停价格 | 对股票为元/股 | 当天向上允许的价格边界。达到涨停时不能假定买单一定能成交；当前股票池用收盘价与其比较形成保守买入标记。 |
| `down_limit` | 跌停价格 | 对股票为元/股 | 当天向下允许的价格边界。达到跌停时不能假定卖单一定能成交；当前股票池据此形成保守卖出标记。 |

**当前处理：** 与未复权 `close` 比较，不能与 `close_adj` 比较。缺失、非有限或非正限价不会被当作相应方向可以成交。日线价格约束只是简化检查，不能证明排队顺序、盘口数量或实际成交能力；当前输出是信号日状态，下一交易日执行时仍须重新核验。

**用途：** 区分市场开市但某只股票停止交易、恢复交易、只停牌部分时段等情况。字段依据：[Tushare每日停复牌信息](https://tushare.pro/document/2?doc_id=214)。

### 从raw走到研究输入：把几张表连起来看

| 任务 | 所需数据与基本操作 | 容易混淆的地方 |
|---|---|---|
